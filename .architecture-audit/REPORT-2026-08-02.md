# BOR-81 / BOR-82 UX and Architecture Report

## Objective

Turn the portfolio from a static resume into a conversion-focused sales experience for business owners and finance leaders, while preserving accessibility, performance, and safe deployment to a shared VM.

## UX benchmark research

Research completed on 2026-08-02.

| Benchmark | Useful pattern | Applied solution |
| --- | --- | --- |
| [Stripe](https://stripe.com/gb) | Leads with business outcomes, then supports claims with metrics, product visuals, and customer proof. | Each case study starts with the finance problem and measurable operational outcome before naming implementation details. |
| [Ramp](https://ramp.com/) | Converts feature density into a simple promise: save time, automate busywork, and connect finance systems. | The hero prioritizes automation, financial analytics, and API integrations instead of a long technology inventory. |
| [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines) | Keeps interaction purposeful, accessible, and respectful of reduced-motion preferences. | The canvas is decorative, capped for device pixel ratio, paused when hidden, and replaced by a static composition for reduced motion. |
| [Abesalom](https://abesalom.com/) | Uses an immersive visual project grid to make a large body of work feel exploratory. | Screenshots float behind the narrative and change with scroll position, but interaction remains linear rather than becoming a 3D game. |

### Three original presentation solutions

1. **Evidence-linked network:** every active network image maps to the case study currently intersecting the viewport, so motion reinforces rather than competes with reading.
2. **ROI-first proof rail:** each dense integration story is reduced to problem, intervention, result, and connected systems.
3. **Two-layer contrast system:** screenshots remain low-opacity background evidence while the active case-study card uses an opaque slate surface and short text measure.

## Architecture findings and fixes

### 1. Public confidential documents

- **Finding:** blurred finance previews still shipped the original PDFs in `public/`, making them directly downloadable.
- **Five whys:** PDFs were public because previews needed URLs; URLs came from a generated manifest; the manifest treated visual hiding as authorization; no server authorization layer existed; a static site cannot protect bundled secrets.
- **Fix:** removed all protected PDFs, their manifest generator, viewers, upload helpers, and an explicit Nginx rule now rejects the old path.

### 2. Background animation cost and readability

- **Finding:** unconstrained motion could obscure content and waste CPU on the shared client device.
- **Five whys:** decorative particles animated continuously; visibility was not observed; edge work could grow with nodes; pixel ratio was uncapped; reduced-motion behavior was incomplete.
- **Fix:** introduced a bounded canvas graph with precomputed edges, 24/44 node limits, DPR capped at 1.5, tab visibility pausing, Intersection Observer activation, and a static reduced-motion render.

### 3. Resume-oriented content hierarchy

- **Finding:** the old interface centered personal style and a technology list rather than buyer outcomes.
- **Five whys:** content was organized by resume sections; capabilities lacked business context; project evidence was separated from claims; CTAs were generic; visitor intent was never expressed in the information architecture.
- **Fix:** rebuilt the home and projects pages around reconciliation, delivery economics, banking analytics, ERP synchronization, and a workflow-review CTA.

### 4. Unsafe shared-VM deployment

- **Finding:** the former workflow printed configuration, used a long-lived JSON key, mutated Compose with `sed`, managed Caddy, and could affect unrelated services.
- **Five whys:** one workflow owned too many responsibilities; credentials were treated as build data; deployment used mutable tags; rollback state was not preserved; shared infrastructure boundaries were undocumented.
- **Fix:** moved to Workload Identity Federation, immutable commit images, SSH host fingerprint verification, one isolated Compose service, strict resource limits, health-gated rollback, and no Caddy lifecycle commands.

### 5. Stale and dead application paths

- **Finding:** unused visualization, upload, email, and PDF components increased maintenance and dependency exposure.
- **Five whys:** experiments accumulated; routes changed; dead imports were not systematically removed; dependencies remained after features disappeared; no focused test suite guarded the live conversion path.
- **Fix:** deleted dead paths and unused packages, added route error handling, a 404, lint configuration, Vitest tests, and production build verification.

## Performance and accessibility design

- Canvas decoration is `aria-hidden` and cannot intercept pointer input.
- Intersection Observer performs section activation without scroll-event polling.
- Images are generated as compressed WebP and lazy-loaded.
- Keyboard focus is visible; navigation exposes state and mobile menu semantics.
- `prefers-reduced-motion: reduce` disables canvas animation and nonessential transitions.
- Exact 60 fps cannot be guaranteed on every device; the implementation minimizes frame work and must be confirmed with browser profiling on representative hardware.

## Asset pipeline

- Sources: `assets/source-screenshots/`
- Mapping: `config/portfolio-assets.json`
- Command: `npm run assets:build`
- Optimized output: `public/projects/network/`
- Generated import manifest: `src/generated/projectAssets.json`

Only screenshots approved for public display belong in the source directory. Never add credentials, customer personal data, or confidential transaction details.

## Validation gates

- TypeScript: `npx tsc --noEmit`
- Lint: `npm run lint`
- Tests: `npm test`
- Production bundle: `npm run build`
- Container config: `IMAGE_URI=example.invalid/portfolio:test docker compose -f secure-docker-setup/docker-compose.yml config`

## Deferred risks

- User-supplied outcome metrics were not available, so copy avoids invented percentages and monetary claims.
- The contact form opens the visitor's email client; a server-side lead endpoint remains intentionally out of scope.
- Browser performance should be profiled on the exact lowest-end mobile device used for acceptance testing.
